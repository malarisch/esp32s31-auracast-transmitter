# AES67 → Auracast Bridge (ESP32-S31) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Firmware für das ESP32-S31-Function-CoreBoard-1, die 48-kHz-Stereo-PCM als I2S-Slave vom FPGA empfängt und als Auracast-Broadcast (LC3, 2 BIS) aussendet. Die Taktabweichung PTP ↔ Quarz gleicht ein geregelter Software-Resampler aus.

**Architecture:** Der I2S-DMA-Interrupt kopiert die Frames in einen Lock-free-Ring und merkt sich Zeitstempel. Ein Encoder-Task wird pro bestätigtem SDU vom BLE-Controller angestoßen. Er schätzt den Ring-Füllstand, regelt per PI-Regler das Verhältnis eines polyphasen Float-Resamplers, erzeugt 480 Frames pro Kanal, codiert sie mit LC3 und sendet zwei SDUs (L/R). Die DSP-Bausteine (Ring, Resampler, Regler) sind reines C ohne IDF-Abhängigkeit und werden auf dem Host getestet.

**Tech Stack:** C11, ESP-IDF `release/v6.1` (Target `esp32s31`, Preview), ESP-BLE-AUDIO + Bluedroid, `espressif/esp_audio_codec` ~2.6 (LC3), CMake/CTest + gcc für Host-Tests, pyserial für Log-Mitschnitte.

**Spec:** `docs/superpowers/specs/2026-10-17-auracast-s31-design.md`

## Review Focus

1. **I2S-Takt fällt weg und kommt wieder** (FPGA-Rekonfiguration, PTP-Verlust): Der Broadcast läuft mit Stille weiter und geht ohne Neustart zurück auf `RUN`. Getestet in Task 7 (Gap-Test).
2. **„sent“-Callbacks bleiben aus oder gehen verloren** (Controller-Queue leer, Sendefehler): Das Pacing heilt sich selbst durch Auffüllen auf die Queue-Tiefe und einen Watchdog nach 50 ms. Getestet in Task 6 (Skip-Send-Debugoption).
3. **FPGA liefert falsche Rate** (z. B. 44,1 kHz oder grob verstimmt): Der Regler meldet `OUT_OF_RANGE`, die Pipeline sendet Stille und loggt einen Fehler, der Puffer flattert nicht. Getestet in Task 4 (+2000 ppm) und Task 7 (Zustand bei OUT_OF_RANGE).
4. **Reihenfolge beim Start**: I2S-Signal kommt vor oder nach dem BLE-Stream. Beide Reihenfolgen erreichen `RUN`. Getestet in Task 7 (Testton mit Startverzögerung).
5. **Vollaussteuerung**: Gibbs-Überschwinger des Resamplers dürfen nicht überlaufen und das Vorzeichen kippen. Getestet in Task 3 (Rechteck mit 0,95 FS).

- [ ] **Step 3: `resampler.c` implementieren**

Algorithmus (wird durch Signatur und Tests nicht festgelegt):
- Prototyp-Kernel `h(t) = 2·fc·sinc(2·fc·t)·kaiser(t, β)` mit `fc = 0.45` (normiert auf 48 kHz), Startwert `β = 9.5`, Stützbereich `t ∈ (−TAPS/2, TAPS/2]`.
- Tabelle `coef[RESAMPLER_PHASES + 1][RESAMPLER_TAPS]` als `float`, berechnet in `resampler_create`. Phase `p` entspricht dem Bruchteil `p/PHASES`. Jede Zeile wird auf Summe 1 normiert (DC-Verstärkung exakt 1 für jede Phase). Zeile `PHASES` ist Zeile 0, um ein Frame verschoben, damit die Interpolation zwischen den Phasen über die Ganzzahlgrenze stetig bleibt.
- Interner linearer Float-Puffer pro Kanal: `TAPS` Frames Historie plus Neueingang. `push` wandelt mit `1/2147483648.0f` um. Nach jedem `pull` werden die verbrauchten Frames herausgeschoben, die Historie bleibt.
- Position `pos` als `double` relativ zum Pufferanfang. Pro Ausgabe-Frame gilt `i = floor(pos)`, `φ = (pos − i)·PHASES`, `p = floor(φ)` und `a = φ − p`. Daraus `y = dot(x[i…], coef[p]) + a·(dot(x[i…], coef[p+1]) − dot(x[i…], coef[p]))`. Anschließend `pos += ratio`.
- Ausgabe: `y·2147483648.0f` wird auf `[INT32_MIN, INT32_MAX]` begrenzt, und zwar vor der Umwandlung in den Integer.
- `resampler_input_needed` gibt `max(0, ceil(pos + (out_frames−1)·ratio) + TAPS − gepufferte Frames)` zurück, plus 1 Sicherheits-Frame.

- DMA-Blöcke à 240 Frames treffen zu `k·240/(48000·(1+eps))` s ein. Der ISR-Zeitstempel bekommt einen gleichverteilten Jitter von ±20 µs (LCG mit `seed`).
- Ringkapazität 4096. Zuerst Priming: der Regler läuft erst, sobald der Zählerstand ≥ 960 ist.
- Pro Tick: `fill_estimate(...)`, dann `drift_ctrl_update(est, 0.010)`. Verbraucht werden `floor(acc += 480·ratio)` Frames.
- Ergebnis: `final_ppm` (Mittel der letzten 10 s), `final_fill_err` (Mittel von est − 960 der letzten 10 s), `ppm_pp_last60s`, `min_count_before_consume` (nach dem Priming), `max_count`, `out_of_range`, `out_of_range_at_s`.

```c
static void test_converges_plus(void)  /* eps +41.7, 300 s: |final_ppm-41.7|<1.0, |final_fill_err|<24, min>=544, max<=3856, pp<1.0 */
static void test_converges_minus(void) /* eps -100, 300 s: |final_ppm+100|<1.0, min>=544, max<=3856 */
static void test_step(void)            /* +50 -> -50 at 150 s, 400 s: |final_ppm+50|<1.0, min>=544, max<=3856, !out_of_range */
static void test_out_of_range(void)    /* eps +2000, 60 s: out_of_range && out_of_range_at_s <= 30 */
```

- [ ] **Step 2: Tests laufen lassen, Fehlschlag prüfen** — Expected: FAIL bzw. Link-Fehler.

- [ ] **Step 3: `drift_ctrl.c` implementieren**

- `fill_estimate` = `count + clamp((t_now − t_isr)·fs/1e6, 0, dma_frames)`.
- `update` berechnet zuerst den Tiefpass `fill_lp += (est − fill_lp)·dt/(tau + dt)`. Beim ersten Aufruf wird `fill_lp = est` gesetzt.
- Danach `e = fill_lp − target` und `ratio = 1 + kp·e + ki·integ`, begrenzt auf ±`max_ppm`·1e-6.
- Anti-Windup: `integ += e·dt` nur, wenn das Verhältnis nicht begrenzt ist oder `e` aus der Begrenzung herausführt.
- `clamp_time_s` zählt hoch, solange begrenzt wird, sonst wird es auf 0 gesetzt. Ab `out_of_range_s` wird `DRIFT_OUT_OF_RANGE` zurückgegeben.
- Herleitung der Default-Gains: Strecke `de/dt = 48000·(eps − (ratio−1))`, Ziel ωn = 0,126 rad/s und ζ = 1. Daraus `ki = ωn²/48000` und `kp = 2ζωn/48000`. Verfehlen die Tests die Schwellen, werden nur die Gains bzw. `tau` getunt, nicht die Schwellen.

- Produces: `typedef enum { PIPE_NO_SIGNAL, PIPE_PRIME, PIPE_RUN, PIPE_RATE_ERROR } pipe_state_t;` (Log-Namen `NO_SIGNAL`, `PRIME`, `RUN`, `RATE_ERROR`, dazu `SYNTH` für die Synth-Quelle).

- [ ] **Step 1: I2S-Quelle in den Encoder-Task einbauen**

Der Encoder-Task ruft `i2s_in_start` selbst auf, damit der ISR auf Core 1 landet. Bei `AURACAST_TEST_TONE` startet er nach `AURACAST_TEST_TONE_START_DELAY_MS` auch `test_tone_start`. Ring: 4096 Frames × 2 Kanäle, statisch im internen RAM.

Pro Paar, abhängig vom Zustand:
- `NO_SIGNAL`: Stille codieren. Ist `signal_present`, `spsc_ring_drop_all`, dann `resampler_reset` und `drift_ctrl_init` und weiter nach `PRIME`.
- `PRIME`: Stille codieren. Ist `ring_count ≥ AURACAST_FIFO_TARGET_FRAMES`, weiter nach `RUN`. Das erste `RUN`-Paar bekommt eine lineare 480-Frame-Einblendung.
- `RUN`:
  1. `est = fill_estimate(snapshot…, 48000, I2S_IN_DMA_FRAMES)` und `st = drift_ctrl_update(est, dt)`, wobei `dt` die gemessene Zeit seit dem letzten `RUN`-Paar ist, begrenzt auf [0,005; 0,05] s.
  2. `resampler_set_ratio(drift_ctrl_ratio())`, dann `need = resampler_input_needed(480)`.
  3. Ist `ring_count < need`: `underrun++`, nach `PRIME`, dieses Paar ist Stille.
  4. Sonst `need` Frames lesen, `push`, `pull(480)`, codieren.
- Übergänge:
  - `!signal_present`: `lost++`, nach `NO_SIGNAL`.
  - `st == DRIFT_OUT_OF_RANGE`: nach `RATE_ERROR` mit `ESP_LOGE("pipeline", "input rate out of range (%+.0f ppm), check FPGA sample rate", ppm)`. Dort Stille codieren, nach 5 s zurück nach `NO_SIGNAL`.
  - Steigt `overflow_frames` seit dem letzten Paar: `ovf += Δ`, nach `PRIME`.
- `fill` und `ppm` aus der Statistikzeile zeigen `est` und `drift_ctrl_ppm()`.
